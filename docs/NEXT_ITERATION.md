更新日期：2026-10-09。开发 Branch 为 `refs/heads/v0.3.0`，应用 `0.3.0-dev.0`，未发布；线上仍为 `0.2.1`。本文件不含真实用户记录、服务配置或凭据。

## P1：个人食材与采购联动

本地代码及离线回归已完成，尚未部署或完成手机验收。

- 在“调整这一餐”中修改、增加或移除食材，填写数量、单位和采购分类；每餐 1–30 项，数量为 0.001–100000，最多三位小数。
- 先预览采购变化，再明确确认保存；预览不会写入，取消预览不改变当前餐单。预览期间餐单、采购状态或身份变化时要求重新核对。
- 同分类、同单位、规范化后同名的食材合计；不同单位不猜测换算。仅统计选中的晚餐，不把运动/不运动两个备选同时计入。
- 实际数量变化的采购项需要重新勾选；未变化项保留。只改餐名/做法或未选中的备选餐，不取消当前采购勾选。
- 个人调整保存在原有 `mealOverrides`，不改写基础餐单、其他餐食或历史；恢复原餐使用相同采购重算逻辑。
- 旧的文字食材说明保留，不猜测其中的份量。完整结构化餐单可以把用量明确改成新方案；没有完整食材结构的旧餐单仍只编辑文字，并明确提示不自动更新采购。
- 输入非法时拒绝本次修改，不能退回默认状态而丢掉已有餐单。断网时保留当前身份的待同步修改，明确提示尚未云端保存；后续重试继续同步。

### 数据兼容与部署顺序

个人食材阶段 schema 从 v8 增量到 v9，新增 `mealOverrides[mealId].ingredientItems` 可选数组；单餐候选阶段到 v10，增加只允许存在于候选中的替换范围；当前条件保存阶段到 v11，新增独立条件与可选份量/时间元数据。旧餐单不补造人数或时间，不绑定新偏好的已有食材；v8–v10 的喝水设置、提醒版本、餐单与采购等均保持，v1–v7 继续原有迁移。不会重建集合、清空文档或批量补写个人记录。

共享采购、条件、单餐范围及收藏逻辑同时进入小程序、`userData`、`aiPlanner`。`userData` 事务内重新验证食材和受影响勾选，不信任客户端计算；收藏增量为 schema v12，当前独立软偏好增量到 v13，保存要求 `clientSchemaVersion: 13`。旧客户端保存会得到升级提示，不能覆盖新字段。

不能单独把 schema v13 的 `userData` 部署到仍供旧客户端使用的正式环境，也不能让旧 `aiPlanner` 写回新文档。当前生成器 planner v10、任务 schema v6；旧 worker/维护程序对高版本任务必须拒绝写入。先在测试环境使用同一冻结源码部署兼容的 `aiPlanner`、`userData` 与 `mealAiMaintenance`，验证新版小程序，再安排正式切换窗口与客户端升级；旧 worker 必须已退出或结束，不能新旧写入器并行。单餐任务要求用户状态已完成当前 schema 升级；AI 队列不自行执行用户数据迁移。条件的 AI 契约/管线及原生输入已在 P3 本地接通，仍需真实云端与原生验收。此轮没有进行任何云端迁移、部署或上传，不将 Git 提交等同于发布。

## P2：只换一餐（服务及页面已接通，待原生与云端验收）

“这顿换一个”“今天不运动了”应产生单餐候选，展示原餐与新餐及采购差异，再确认替换。请求绑定原餐单 ID、餐位 ID、revision 和本次同意；失败、超时、取消或版本冲突保留原餐。其他日期、个人调整和历史不能被整单覆盖。优先复用现有 AI 任务、候选与幂等机制，开始前先检查 GitHub 方案和许可证。

本地服务层已实现，不能描述为手机已可用：

- 单餐任务复用现有队列、速率限制、显式 AI 同意与随机请求 ID。服务端绑定所选餐单/日期/餐次、原餐内容及晚餐模式；绑定信息进入任务指纹，但不进入发给 AI 的偏好正文。
- 只接受一天一个餐次，不允许夹带其他日期、双晚餐或客户端身份字段；有未处理候选时不覆盖它。单餐偏好不改写整单偏好。
- 生成成功只保存带范围的候选，原餐与采购不动；原餐变化时冲突终止，非法候选终止并释放任务。完成或过期的任务清除源餐快照，只保留用途与审计字段。
- 普通 `confirmDraft` 拒绝单餐候选。专用事务确认校验候选 ID、预览 revision、身份代际及有效期，只更新对应的个人餐食；基础餐单、其他日期、历史和提醒保持。
- 同时切换晚餐模式与食材时，按切换前后的实际总用量取消受影响勾选；总量未变的勾选保留。这里只调整餐食搭配，不改写健康页的实际运动打卡记录。
- 已添加虚构 1/7/14 天单餐确认、冲突与迁移用例，云函数模拟覆盖幂等、范围拒绝、候选覆盖保护、取消/失败保留原餐、账户隔离及旧整单确认拒绝；不是实际 AI 或手机验收。
- 本阶段本地验证：`node scripts/validate.js` 62 组（包括 AI 云函数 76 项用例）、自动化工具 75 项与 AI 发布探针离线 32 项通过；安全扫描未发现实际配置或用户数据。此结果不证明页面、云端部署或手机功能可用。
