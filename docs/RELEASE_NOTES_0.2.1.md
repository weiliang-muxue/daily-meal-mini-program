# 0.2.1 微信更新说明

日期：2026-10-08。当前为更新候选，不代表本轮已经上传、审核或发布。此前版本已由所有者确认上线，本轮不重置任何云端用户数据。

## 可粘贴到微信的更新说明

支持管理员邀请最多 10 位成员，新增仅管理员可见的成员备注；生成前可填写想吃的菜品或食材，改善采购清单同步失败提示和重试。保留已有餐单、记录及有效邀请，不重置用户数据。

## 本轮内容

1. 一位管理员可邀请最多 10 位成员，总容量 11 人；待使用邀请占位、一次性兑换、7 天有效期及管理员权限隔离保持不变。
2. 在“我的 → 已加入成员”管理独立的成员备注：最多 100 字，可修改或清空，只有当前管理员可读写。它与邀请时的备注分开，不授予管理员读取别人的餐单、体重、运动或照片的权限。
3. 采购勾选同步失败时说明尚未保存到云端，保留本机修改并提供重试，不持续快速自动请求。
4. 开发目录分离。只在 `源码仓库` 修改/测试/提交；`微信导入包` 自动生成、只用于开发者工具验证与上传，旧包保留为可恢复副本。
5. 定制餐单“目标与风格”步骤增加明确的“这次想吃什么”入口，并在生成确认时独立展示。沿用已有 `customGoal` 保存和 AI 传递链路，旧补充目标不会丢失，不新增重复字段或改变生成器版本。

## 发布顺序

1. 在源码目录运行完整验证和安全扫描，再运行 `node scripts/build-wechat-package.js`。开发者工具导入同级 `微信导入包`，不要继续打开旧项目根目录，也不要在导入包直接修改源码。
2. 保持原 AppID、云环境与云函数环境变量不变。先部署 `membership` 与 `privacy`（上传并安装依赖），不要部署或运行 `ownerBootstrapOnce`，也不要重新初始化集合。
3. 在原环境验证旧成员、旧邀请码仍有效，总容量显示 11；由管理员新增/修改/清空测试备注，再以普通成员核实无入口且服务端拒绝请求。验证完成清理虚构测试备注。
4. 验证采购离线勾选、失败重试以及旧计划/提醒读取，完成微信开发者工具编译、预览与真机验收后，以 `0.2.1` 上传。更新平台隐私说明中管理员成员备注的处理范围，再走审核和正式发布。
5. 不创建或移动旧版本 Tag。只有对应候选的实际平台发布与源码关系核实后，才建立正式版本快照。

## 回滚与数据保护

本轮仍为用户 schema v8、AI contract v2、planner v7、task schema v3、AI consent v2、provider v10，无新增全库数据迁移。线上故障时应先限制新邀请/回滚界面，同时保留容量 11 的兼容后端；已经超过 4 人后直接回退到容量 4 的旧后端会限制新增并可能撤销超额待用邀请，不能作为无损回滚方案。任何回滚都不得删除集合、清空成员或恢复旧用户数据库覆盖当前记录。
