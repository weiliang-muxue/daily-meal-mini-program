本轮模块检查点：

schema v6 数据连续性检查覆盖旧 schema v1-v5 迁移、至少 20 份历史往返恢复、64 份显式容量错误、按 `planId` 隔离采购/晚餐状态、revision 冲突重放及离线提醒 pending。应用升级不得清空用户状态；长期历史扩展采用独立归档集合和游标分页，启用前不淘汰现有单文档历史。

AI task schema v2 在启动时只保存规范化 `activePlan` / `draftPlan` 的稳定摘要。finalize 事务允许保留购物、提醒、UI 和餐次覆盖等无关并发更新；计划正文更新、确认、恢复、丢弃或生成偏好变化会使旧任务以 `conflict` 结束，完整用户状态和 revision 不变。缺少摘要的旧活动任务在重放、读取、领取、worker 回写和到期维护路径失败关闭，维护清理不读取用户状态。
