# 发布核对清单

每次功能更新先在 `CHANGELOG.md` 的 `Unreleased` 记录用户可见变化，再按本清单验证。只有所有适用项通过，才允许冻结并上传 `release-candidate` 的最终候选 commit；上传、提交审核和正式发布分别需要仓库所有者明确确认。

## 1. 需求与调研

- [ ] 已写清用户操作顺序、空状态、失败状态和恢复路径。
- [ ] 较大功能已搜索 GitHub 和官方文档，并在 `docs/RESEARCH.md` 记录搜索范围、许可证、维护状态、可复用部分与不采用原因。
- [ ] 没有把“未发现满足完整闭环的成品”表述成“GitHub 没有相关项目”。

## 2. 版本与数据

- [ ] 当前唯一工作版本 Branch 与目标正式版本一致；`main` 仅保存通过门禁的 squash 候选树，历史版本只由 annotated Tags 保留，命令中已区分 `refs/heads/...` 和 `refs/tags/...`。
- [ ] GitHub 已启用匹配 `v*` 的 Tag ruleset，禁止删除和强制更新并限制创建者；本地 `pre-push` 已验证现有版本 Tag 删除和移动均失败。
- [ ] 安全扫描器/Hook/工作流/发布门禁若有升级，已先以独立安全策略变更合入默认 Branch；当前业务 PR 不同时修改扫描器，权威 PR 扫描使用默认 Branch 的受信策略且不执行 PR head 代码。
- [ ] 候选 Branch 门禁使用完整 `refs/heads/vX.Y.Z` 上下文，且同版本 Tag 不存在；合入 `main` 后 tree OID 与当前版本 Branch 完全一致，没有使用短名称、偏离候选树的默认 Branch 或 lightweight Tag 绕过门禁。
- [ ] `release-manifest.json`、代码常量和 `CHANGELOG.md` 一致。
- [ ] 模块提交仍保持同一开发版本；发布冻结时才把预发布版本归档为不带 `-dev` 的正式版本号，并把状态设为 `release-candidate`，不能提前标记 `released`。
- [ ] schema 变化只做向前迁移，旧字段和未知未来字段不会被旧客户端整份覆盖删除。
- [ ] 使用脱敏的 v1 至当前版本样本完成迁移测试。
- [ ] schema v6 到 v7 只更新生成偏好的 AI contract v2 标记，不重写 `activePlan`、`draftPlan` 或 `planHistory`；历史 contract v1 与 legacy contract v0 计划均可查看、确认和恢复。
- [ ] 旧版本服务遇到未来 schema 会返回升级提示且不写入，不能把未来数据降级覆盖。
- [ ] 应用升级不会自动替换 `activePlan`；AI 新计划必须经用户预览和确认。
- [ ] 新计划确认失败时，上一份已确认计划和采购勾选仍可恢复。
- [ ] 同一微信号换设备可恢复，第二微信号无法读取前一用户数据。

## 3. AI 契约

- [ ] 餐次数量、任意 1–14 天周期（默认 1 天）、逐日运动和可选双晚餐均按用户选择生成，不依赖固定两餐结构。
- [ ] 周期输入在空白、0 或负整数失焦后归一为 1；小数、非数字和 15 天保持可见错误并阻止生成；1、10、14 天均能进入生成流程且云端从不收到 0 天。
- [ ] 新请求和新计划使用 AI contract v2、planner v7；生成器或契约不匹配的活动任务明确失败关闭，不由当前 worker 静默继续。
- [ ] 云函数校验请求、响应、枚举、数量、长度、响应体大小和超时。
- [ ] 七个正式云函数的候选源码均显式配置 60 秒超时和 256 MB 内存，并已通过本地静态门禁。
- [ ] AI 失败保留上一计划且不使用静态食谱冒充新结果；仅网络、超时、限流等瞬时故障显示重试，鉴权、订阅组、模型、路由或请求配置故障显示管理员检查提示且不鼓励重复提交。
- [ ] 使用允许云函数服务端应用调用的有效 Key 分组完成至少一次真实 1 天候选餐单，确认提纲、详情、完整校验和候选预览全部成功；HTTP 400/403、有效订阅缺失、Responses 权限或模型映射未确认时不得把 AI 主线标记为通过。
- [ ] 每次新生成均默认不勾选 AI 数据同意；修改发送内容会撤销旧同意，客户端、云函数、任务和维护路径共同拒绝缺少当前同意协议的调用。
- [ ] `AI_API_KEY`、`AI_API_BASE_URL`、`AI_PROVIDER_DISPLAY_NAME`、`AI_PROVIDER_REVISION` 已由部署者本人配置在 `aiPlanner` 云函数环境变量；客户端、日志和仓库不包含真实 Key，URL 为合法 HTTPS Responses 基础地址，展示名准确描述数据接收方，revision 为正整数。
- [ ] 只轮换同一数据接收方的 Key 时保持 provider revision 不变；URL、实际数据接收方或展示名任一变化时提高 revision。旧活动任务以 `AI_DATA_CONSENT_REQUIRED` 关闭，用户必须重新确认发送；不存在更换接收方却沿用旧授权的路径。
- [ ] provider 请求契约 v9 固定使用根域 `/responses`、`gpt-5.6`、Responses 和 `store:false`，不主动附加未声明的推理强度；云函数只发送标准 Bearer 鉴权和 JSON 内容头，不发送 provider 专用鉴权或兼容头。
- [ ] `aiPlanner` 无任务状态返回的 `providerContractRevision` 与发布清单一致，`providerRevision` 为本次配置的正整数且展示名正确；旧 v8、缺失或其他版本不匹配的云函数使页面和发布探针保持维护状态。公开状态不包含服务端点、请求头值、Key、配置指纹或用户数据。

## 4. 隐私与安全

- [ ] 未提交 AppID 本机配置、Key、Secret、Token、openid 或 unionid。
- [ ] 首次管理员只由云数据库控制台批准的短期请求创建；未批准、篡改、过期和带终端身份的 `activate` 均被拒绝，并发只能成功一次。`SOURCE=wx_devtools` 未被当作授权，初始化后云端已删除 `ownerBootstrapOnce`。
- [ ] 正式部署只通过 `scripts/deploy-production-function.ps1` 逐个执行七个白名单函数；门禁已拒绝 `ownerBootstrapOnce`、通配符、根目录、路径和全量部署，且当前环境已与独立发布记录中批准的 SHA-256 指纹匹配。
- [ ] 未提交饮食、运动、体重、照片、位置、日志或数据库导出。
- [ ] 数据库继续拒绝客户端直接访问，云函数按 openid 校验成员和数据归属。
- [ ] 受邀账号只能成为普通成员，不能创建邀请、管理成员或造成第二名管理员。
- [ ] 正式邀请码为 32 位大写十六进制且明文只返回一次；待使用列表不含明文、摘要或身份字段。撤销、重复撤销、已兑换和撤销/兑换并发均未造成重复释放名额。
- [ ] 唯一管理员仍有活跃成员时删除会被阻止；只有显式选择并确认 `transferOwner` 后才能继续，不存在自动提升路径。
- [ ] 普通成员清理后成员文档已移除；唯一且无其他成员的管理员在全部私人集合验证清空后，只恢复全新随机 `memberRef` / `cacheNamespace` 的最小身份，旧本地缓存无法重新绑定，失败重试期间不能写入私人数据。
- [ ] 新增敏感能力已更新隐私说明、删除路径和最小化采集策略。
- [ ] 可选手机号已在真机验证用户主动点击、拒绝、成功、动态 code 过期、主体/认证/计费/额度不支持路径；完整号码与动态 code 不进入数据库、本地缓存、日志、Git 或公开响应。
- [ ] 头像使用微信原生 `chooseAvatar`、昵称使用原生 `type="nickname"`；两者均可跳过和后续修改，代码未使用已废弃的 `getUserInfo` 自动获取完整资料。
- [ ] 门禁验证前和“我的”页均可用至少 44pt 热区打开《用户协议》和《隐私保护指引》；平台合同打开失败会进入本地隐私说明。
- [ ] 应用启动不会强制隐私同意，也没有自绘仿冒授权弹窗；头像、相机和相册仅在用户主动操作时按微信平台流程授权。
- [ ] 真机分别验证无需授权、首次授权、拒绝后就近错误、重试、打开合同，以及旧基础库原生拦截；拒绝时敏感动作未继续。
- [ ] `node scripts/check-staged-safety.js` 通过。
- [ ] `pre-push` 已扫描即将推送的完整提交范围；任何在中间提交出现后又删除的敏感内容同样会阻止推送。
