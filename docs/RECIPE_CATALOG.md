# 本地菜谱搜索：独立数据接入阶段

2026-10-09，`v0.3.0` 功能分支，尚未发布。此决策不改变线上 `0.2.1`，也不把第三方内容加入旧发布候选。

## 目标与本阶段边界

最终提供无需调用 AI 的本地菜谱搜索、食材与做法查看、明确的开源与数据来源入口。用户的私人收藏、不喜欢、过敏忌口、现有餐单及采购状态不与公共数据混写。来源的文字用量不是结构化采购用量；不执行配方表达式、不猜人数、不自动安排进餐单或采购。

先完成可复现导入，再审核内容和来源路径，最后连接搜索界面。本阶段只有独立构建工具及测试，**没有运行时菜谱数据、没有搜索页面上线**。工具不会自动把全部候选视为审核通过，也没有写入小程序目录或数据库的命令。

## 输入与获取

固定来源及边界沿用 `THIRD_PARTY_DATA_EVALUATION.md`，本次选择 `json/recipes.json` 为唯一权威详情，索引只用于映射。实际使用的上游 HowToCook 生成 commit 仍是 `unknown`；独立许可证核验 commit 不冒充生成版本，也不等于每个路径已经核验。

`scripts/recipe-catalog-source.js` 固定四个公开输入的仓库、commit、路径、字节数和 SHA-256：两份 LICENSE、`json/index.json`、`json/recipes.json`。不下载代码、图片、SQLite、LFS、最新分支或额外清单。不读取任何本机/云端 AI 配置，不携带令牌或 Cookie，拒绝跳转和超限响应。

在源码仓库运行（获取步骤需要网络；审核生成步骤不需要网络）：

```powershell
node scripts/fetch-recipe-catalog.js
node scripts/recipe-catalog-import.js
node scripts/test-recipe-catalog-import.js
```

输入在忽略目录 `.local/recipe-catalog/<固定 commit>/inputs`，审核输出在相邻 `review-v1-<结果摘要前缀>`；不会进入 Git 或微信导入包。脚本不接受任意下载地址、目录或发布参数。目录连接/符号链接拒绝，已有不一致文件拒绝覆盖；重复运行完全相同输入仅核对结果，不更新日期或制造差异。日期是版本输入，不是运行当天时间。

## 校验与最小化

- 四份输入逐字节校验，包含许可证；未知文件或另一种详情表示混入时拒绝。输入丢失、下载失败或哈希改变不会退回网页/API。
- 严格字段与类型、唯一 ID、索引/详情来源一致、相对 Markdown 路径、连续步骤及文本长度检查。重复来源路径隔离全部相关条目，不任意选一个覆盖。
- 所有图片和路径、摘要、热量、标签、难度及份数公式均不进入候选记录。保留食材文字用量、是否每份、可选性、来源备注、做法和工具，避免删除“只用蛋清”等有意义说明。
- 兼容该固定源的可选空值：步骤 `produces: null` 丢弃；`tips: null` 及数组中的 `null` 视为没有补充提示，其他非字符串不接受。文字中的比较符号不当作 HTML 删除，不改原做法含义。
- 任意 URL、HTML/脚本、控制字符、未知字段或来源冲突隔离并输出稳定原因码；不会打印来源正文或原始异常。已识别的生食、特殊人群、健康/品牌引用、长时间制作或大批量条目额外列入审核提示。
- 每个候选均有原始记录/索引/转换后摘要、固定来源、许可证摘要、转换步骤和 `content: pending`。关键词检查仅帮助排序，不证明食物安全、过敏安全或权利清晰；无提示的条目也必须审核。

## 后续门禁与回滚

本次实际准备结果：四份固定输入哈希均一致；364 条源记录中 342 条仅通过结构筛查，22 条隔离（14 条共享同一原路径、8 条含外部链接）。78 条候选带额外内容提示；每条候选的内容与健康审核仍为待办，`releaseReady` 保持 `false`。源数据还存在较长静置时间与总时长标注口径差异，保留原值并标记 `DURATION_BASIS_REVIEW`，不能直接复用为本项目的烹饪时间承诺。

1. 核对原路径存在及来源关系；逐项审核文字、食材、用量、份量、做法与第三方引用。明确记录接受/拒绝与证据，不能把当前自动筛选当作审核完成。
2. 用显式绑定记录摘要的审核清单生成基础数据；补齐仓库 `THIRD_PARTY_NOTICES.md`、两份许可证原文快照、机器溯源和小程序内“开源与数据来源”，缺一不进入发布包。
3. 搜索支持菜名/食材、分类、分批显示、无结果与返回保留查询；采用微信原生控件与既有主题，不热链、不引入网页组件。显示原份量、来源时间估计和适用边界；不能声称医疗适配。
4. 验证完整包大小、离线搜索、用户切换、来源入口、窄屏/大字体/深色模式；实际开发者工具及 Android/iOS 证据单独记录，测试桩不能代替。

回滚仅撤下新公共菜谱入口或对应数据版本；不重建集合、不清空私人记录、不回退用户 schema，也不覆盖已保存个人菜谱。当前工具仅产生隔离的本地审核文件，因此不会改变任何线上用户数据。
