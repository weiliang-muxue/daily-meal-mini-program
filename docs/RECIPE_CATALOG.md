## 目标与本阶段边界

最终提供无需调用 AI 的本地菜谱搜索、食材与做法查看、明确的开源与数据来源入口。用户的私人收藏、不喜欢、过敏忌口、现有餐单及采购状态不与公共数据混写。来源的文字用量不是结构化采购用量；不执行配方表达式、不猜人数、不自动安排进餐单或采购。

已按“可复现导入 → 内容及路径检查 → 原生界面”接通两批共 13 道菜，当前数据版本 `2026-10-09.2`。入口为“我的收藏 → 去菜谱库找灵感”，来源也可从“我的 → 开源与数据来源”查看。**开发线已有运行时数据和搜索页面，尚未部署或上线**。只在用户主动点击时复制菜名或公开来源链接，没有第三方网络请求，不读写私人收藏/餐单/采购。首次身份验证仍需联网；已验证会话中的搜索使用随包数据。

## 输入与获取

固定来源及边界沿用 `THIRD_PARTY_DATA_EVALUATION.md`，本次选择 `json/recipes.json` 为唯一权威详情，索引只用于映射。实际使用的上游 HowToCook 生成 commit 仍是 `unknown`；独立许可证核验 commit 不冒充生成版本。已在固定核验快照完整 Git tree 中确认 342 个候选路径存在；存在不代表内容正确、也不证明生成时的版本。

`scripts/recipe-catalog-source.js` 固定四个公开输入的仓库、commit、路径、字节数和 SHA-256：两份 LICENSE、`json/index.json`、`json/recipes.json`。不下载代码、图片、SQLite、LFS、最新分支或额外清单。不读取任何本机/云端 AI 配置，不携带令牌或 Cookie，拒绝跳转和超限响应。

在源码仓库运行（获取步骤需要网络；审核生成步骤不需要网络）：

```powershell
node scripts/fetch-recipe-catalog.js
node scripts/recipe-catalog-import.js
node scripts/test-recipe-catalog-import.js
node scripts/build-recipe-catalog.js --check
node scripts/test-recipe-catalog.js
node scripts/test-recipe-catalog-page.js
```

输入在忽略目录 `.local/recipe-catalog/<固定 commit>/inputs`，完整审核输出在相邻 `review-v1-<结果摘要前缀>`；原始文件与全部候选不进入 Git 或微信导入包。获取/导入脚本不接受任意下载地址、目录或发布参数。目录连接/符号链接拒绝，已有不一致输入拒绝覆盖；重复运行完全相同输入仅核对结果，不更新日期或制造差异。日期是版本输入，不是运行当天时间。

显式决定文件为 `docs/recipe-catalog-review.json`。每条准入记录绑定原始/转换后 SHA-256、原路径、核验 blob 与文字理由；另列暂缓决定。`build-recipe-catalog.js` 无参数时重新校验四份固定输入后，只重建六个固定公共输出（两份运行模块、逐条溯源、两份许可证和 NOTICE），不接受任意路径；`--check` 只核对现存输出，不写文件。改源正文或清单会触发旧摘要失效，需要重新审阅。输出不能当作发布授权。

## 校验与最小化

- 四份输入逐字节校验，包含许可证；未知文件或另一种详情表示混入时拒绝。输入丢失、下载失败或哈希改变不会退回网页/API。
- 严格字段与类型、唯一 ID、索引/详情来源一致、相对 Markdown 路径、连续步骤及文本长度检查。重复来源路径隔离全部相关条目，不任意选一个覆盖。
- 所有图片和路径、摘要、热量、标签、难度及份数公式均不进入候选记录。保留食材文字用量、是否每份、可选性、来源备注、做法和工具，避免删除“只用蛋清”等有意义说明。
- 兼容该固定源的可选空值：步骤 `produces: null` 丢弃；`tips: null` 及数组中的 `null` 视为没有补充提示，其他非字符串不接受。文字中的比较符号不当作 HTML 删除，不改原做法含义。
- 任意 URL、HTML/脚本、控制字符、未知字段或来源冲突隔离并输出稳定原因码；不会打印来源正文或原始异常。已识别的生食、特殊人群、健康/品牌引用、长时间制作或大批量条目额外列入审核提示。
- 每个候选均有原始记录/索引/转换后摘要、固定来源、许可证摘要、转换步骤和 `content: pending`。关键词检查仅帮助排序，不证明食物安全、过敏安全或权利清晰；无提示的条目也必须审核。
